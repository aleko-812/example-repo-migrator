# Инструмент миграции Git-репозиториев

Bash-скрипт для автоматической миграции нескольких Git-репозиториев между системами контроля версий.

Это не инструмент зеркалирования. Скрипт предназначен для разового переноса.

## Обзор

Скрипт переносит Git-репозитории из одной VCS в другую с сохранением всех веток, тегов и истории коммитов.

## Требования

- Git
- Bash
- curl
- SSH-доступ к исходному и целевому Git-серверам
- Настроенные SSH-ключи

## Настройка

1. Клонируйте этот репозиторий
2. Скопируйте `.env.example` в `.env`:
   ```bash
   cp .env.example .env
   ```
3. Отредактируйте `.env`:
   ```
   SOURCE_SSH_BASE="ssh://git@source.example.com:7998/YOUR_NAMESPACE"
   TARGET_ORGANISATION="YOUR_ORGANISATION"
   TARGET_SSH_BASE="ssh://git@target.example.com:7998/YOUR_ORGANISATION"
   TARGET_API_BASE="https://target.example.com/api/v1"
   TARGET_AUTHORIZATION_HEADER="authorization: Basic YOUR_TOKEN"
   WORK_DIR="/tmp/git_migration"
   REPOS_LIST="repos.txt"
   ```

4. Создайте файл `repos.txt` со списком репозиториев для миграции (по одному в строке):
   ```
   repo1
   repo2
   repo3
   ```

## Переменные окружения

- `SOURCE_SSH_BASE`: SSH URL исходного Git-сервера
- `TARGET_ORGANISATION`: имя организации в целевой системе
- `TARGET_SSH_BASE`: SSH URL целевого Git-сервера
- `TARGET_API_BASE`: базовый URL HTTP API целевой системы
- `WORK_DIR`: временный каталог для клонирования репозиториев
- `REPOS_LIST`: путь к файлу со списком репозиториев для миграции
- `TARGET_AUTHORIZATION_HEADER`: заголовок авторизации для API целевой системы (Basic auth)

* Токен для `TARGET_AUTHORIZATION_HEADER` возьмите из документации целевой системы контроля версий.

## Использование

1. Убедитесь, что SSH-ключи настроены и для исходного, и для целевого Git-сервера
2. Запустите скрипт миграции:
   ```bash
   ./migrate_repos.sh
   ```

Скрипт:

1. Проверит, существует ли репозиторий в целевой системе
2. Создаст новые репозитории в целевой системе при необходимости
3. Клонирует репозитории из источника со всеми ветками и тегами
4. Отправит всё содержимое в целевые репозитории
5. Удалит временные файлы

## Возможности

- Полное зеркалирование истории репозитория, включая все ветки и теги
- Пропуск уже существующих репозиториев
- Подробное логирование процесса миграции
- Автоматическая очистка временных файлов
- Проверка обязательных переменных окружения и обработка ошибок

## Обработка ошибок

Скрипт:

- Проверяет наличие обязательных переменных окружения
- Проверяет существование необходимых файлов
- Проверяет успешность создания репозиториев и операций push
- Пропускает уже существующие репозитории, не завершаясь с ошибкой

## Замечания

- Для клонирования используется временный каталог из `WORK_DIR`
- Все временные файлы удаляются после миграции
- Убедитесь, что в рабочем каталоге достаточно места на диске
- История Git сохраняется полностью
